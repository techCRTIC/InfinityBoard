# Contribuir a InfinityBoard | Contributing to InfinityBoard

---

## Español

### ¿Cómo contribuir?

¡Gracias por tu interés en contribuir a **InfinityBoard**! Este proyecto es parte del ecosistema tecnocreativo de **CRTIC** y toda colaboración es bienvenida.

#### Reportar Errores

1. Verifica que el error no haya sido reportado previamente en [Issues](https://github.com/techCRTIC/InfinityBoard/issues).
2. Abre un nuevo issue usando la plantilla de **Bug Report**.
3. Incluye pasos claros para reproducir el error, capturas de pantalla si es posible, y versión del sistema operativo.

#### Solicitar Funcionalidades

1. Revisa los issues existentes para evitar duplicados.
2. Abre un nuevo issue con la plantilla de **Feature Request**.
3. Describe tu idea con el mayor detalle posible.

#### Enviar un Pull Request

1. Haz un fork del repositorio.
2. Crea una rama descriptiva: `git checkout -b feature/mi-nueva-funcionalidad`.
3. Asegúrate de que tu código siga las guías de estilo del proyecto (Prettier + ESLint).
4. Haz commit con mensajes claros y descriptivos.
5. Envía tu Pull Request a la rama `main`.

#### Estilo de Código

- Usamos **Prettier** y **ESLint** para mantener la consistencia.
- Ejecuta `npm run lint` antes de enviar tu PR.
- Sigue las convenciones de nombres existentes en el proyecto.

## English

### How to Contribute

Thank you for your interest in contributing to **InfinityBoard**! This project is part of the **CRTIC** techno-creative ecosystem, and all collaboration is welcome.

#### Reporting Bugs

1. Check that the bug hasn't already been reported in [Issues](https://github.com/techCRTIC/InfinityBoard/issues).
2. Open a new issue using the **Bug Report** template.
3. Include clear reproduction steps, screenshots if possible, and OS version.

#### Requesting Features

1. Review existing issues to avoid duplicates.
2. Open a new issue with the **Feature Request** template.
3. Describe your idea in as much detail as possible.

#### Submitting a Pull Request

1. Fork the repository.
2. Create a descriptive branch: `git checkout -b feature/my-new-feature`.
3. Ensure your code follows project style guides (Prettier + ESLint).
4. Commit with clear, descriptive messages.
5. Submit your Pull Request to the `main` branch.

#### Code Style

- We use **Prettier** and **ESLint** for consistency.
- Run `npm run lint` before submitting your PR.
- Follow the existing naming conventions in the project.
